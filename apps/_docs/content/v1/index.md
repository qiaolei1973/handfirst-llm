# v1：猜一条直线

> 我们先不讲机器学习。先玩一个游戏：让计算机猜一条直线。

---

## 谜题

这里有一堆散点。12 个点，你能看出它们背后藏着一条直线。人眼扫一眼就猜出来了，但计算机不会"看"——它只会算。

![12 个散点分布在坐标平面上，大致沿一条直线排列](/v1/scatter-only.png)
<!-- gen_v1_images.py: #1 scatter-only — 纯散点，12 个蓝点，x∈[0,20], y∈[0,50]，不画线。标题："计算机看到的只有这些点" -->

现在的问题是：**计算机怎么靠自己猜出这条直线？**

其实你认真想一想，计算机只会做一件事：**瞎猜 → 看差多少 → 往正确的方向挪一点点 → 再猜 → …** 反复来，慢慢就接近了。

这不是魔法，就是四步循环。

---

## 第一步：随便猜一个

直线公式你都熟：`y = W·x + bias`。决定一条直线的就是两个数——**W**（斜率）和 **bias**（截距）。

计算机啥都不知道，先随便给一组：W=1，bias=0。也就是猜 `y = 1·x + 0`。

![散点图上叠加了一条 y=1x+0 的直线，严重偏离散点](/v1/initial-guess.png)
<!-- gen_v1_images.py: #2 initial-guess — 散点 + 绿线真实 y=2x+10 + 紫线模型 y=1x+0，大部分点远在模型线上方 -->

显然，猜得很烂。没关系，下一步就是看看有多烂。

---

## 第二步：看猜得有多差

对每一个点，计算机算两样东西：

1. **预测值**：用当前的 W 和 bias 算出来的 y（记作 `yPred`）
2. **真实值**：数据里实际给的 y

然后把它们一减：`diff = yPred - 真实值`。差得越远，说明猜得越烂。

![一个散点被高亮，旁边标注了 yPred、y 真实值、以及两者之差 diff](/v1/one-point-diff.png)
<!-- gen_v1_images.py: #3 one-point-diff — 选第 4 个点标注 diff 竖线，紫标注 yPred，蓝标注真实 y，红标 diff -->

把所有 12 个点的差的**绝对值**加起来——这就是一个"总差评分"。分越低，猜得越准。

![所有 12 个点都画上了红色误差线，底部标注 total=|diff1|+|diff2|+...](/v1/all-points-error.png)
<!-- gen_v1_images.py: #4 all-points-error — 12 条红色误差竖线，右上角红色框标注总差距值 -->

```typescript
// 对应代码（train_simple.ts 的核心几行）：
const diff = yPred - target;
totalLoss += Math.abs(diff);   // 所有点的绝对差距之和
```

不管高了还是低了，绝对值只看"差多远"，不关心方向。

---

## 第三步：往正确的方向改

知道错了，就得改。问题是——**往哪改？**

直觉很简单：
- 预测值**太大**了（diff > 0）→ W 和 bias 要往**小**调
- 预测值**太小**了（diff < 0）→ W 和 bias 要往**大**调
- 预测值刚好（diff = 0）→ 别动

所以只关心 diff 的**正负号**：

```
sign = diff > 0 ? +1（预测大了，往回拉）: -1（预测小了，往前推）
```

![图示：左边一个点 diff > 0（箭头向下示意 W 减小），右边一个点 diff < 0（箭头向上示意 W 增大）](/v1/direction-sign.png)
<!-- gen_v1_images.py: #5 direction-sign — 左右子图对比：diff>0 时 W↓ 往回拉 vs diff<0 时 W↑ 往前推 -->

然后，每个点对 W 的影响还要**乘上它的 x 坐标**——道理也简单：x 大的点，对斜率的影响应该更大（想想杠杆原理）。

```typescript
const sign = diff > 0 ? 1 : -1;  // 只看方向
gradW   += sign * x;              // W 的调整量：方向 × 坐标
gradBias += sign;                 // bias 的调整量：只看方向

// 最后取平均
gradW   /= n;
gradBias /= n;
```

![图示：两个点对比，左边 x=2 对 W 的推力小（箭头短），右边 x=18 对 W 的推力大（箭头长）](/v1/x-leverage.png)
<!-- gen_v1_images.py: #6 x-leverage — 左右子图：x=2 的小推力 vs x=18 的大推力，红色箭头长度差异明显 -->

> 💡 这里有一个细节：gradW 是**所有点调整量的平均值**。每个点都有自己的意见（"往大调！""往小调！"），取平均就是"少数服从多数"。

---

## 第四步：走一小步

方向有了，但不能一步迈太大。步子太大容易跳过最优解，太小又爬半天不动。

用一个**学习率**（0.1）来控制步长：只取调整量的 10%。

```typescript
W    -= 0.1 * gradW;
bias -= 0.1 * gradBias;
```

![经过一步更新前后对比，直线微微向散点靠近](/v1/one-step.png)
<!-- gen_v1_images.py: #7 one-step — 并排对比：左=更新前（W=1.00, bias=0.00）vs 右=一步梯度下降后（W≈1.2, bias≈0.6），误差线均缩短 -->

---

## 重复，重复，重复

四步做完一轮，回到第一步，用更新后的 W 和 bias 重新再猜。每次都比上一次准一点点。

做 600 轮之后：

```
训练完成，W: 1.9945, bias: 10.1302
```

真实值是 W=2, bias=10。**已经非常接近了。**

## 但是...

线猜对了，对吧？W ≈ 2，bias ≈ 10，看起来不错。

但你注意到几个不对劲的地方了吗？

### 问题一："评分"为什么一直是 0？

看状态栏——**Loss 永远是 0.0000**。Loss 曲线也是一条平线。但我们明明看到初始时那条线差得有多远——总差距怎么可能是 0？

不是 bug，是 v1 的实现里**压根没算** Loss。`_step()` 里把 loss 写死为 0 了。

这不单是"没显示"的问题。这暴露了一个更深的问题：我们的算法根本不关心**差了多少**，它只看**方向**。差 0.01 和差 100，对它的推动力是一样的——

### 问题二：步子大小不会自己调整

![MAE 的损失：L = |diff|，V 形](/v1/mae-loss.png)
<!-- gen_v1_images.py: #8 mae-loss — 红色 V 形 L=|diff|，辅助线标出差±5→L=5 -->
![MAE 的梯度：grad = sign(diff)，只看方向](/v1/mae-gradient.png)
<!-- gen_v1_images.py: #9 mae-gradient — 红蓝分段 grad=sign(diff)，标注差100/差0.01推力都是±1 -->

每个点只看方向（`sign`），不看差多远。这就好比开车——不管离目的地 1 公里还是 100 公里，油门都踩同样的深度。快到目的地了也不会减速。

### 问题三：W 跑得快，bias 爬得像蜗牛

![W 和 bias 的收敛速度对比](/v1/loss-comparison.png)
<!-- 已有图片：并排两个 loss landscape。左=L(W) 几个大步到谷底，右=L(bias) 密密麻麻很多步才到谷底 -->

同样的学习率、同样的轮数——W 早就到位了，bias 还在慢慢蹭。

原因藏在第三步的逻辑里：W 的调整量乘了 `x`（x 最大能到 20，相当于加了杠杆），bias 的调整量永远是 `±1`。一个拿杠杆，一个用手推。

![W 和 bias 的梯度量级对比](/v1/gradient-asymmetry.png)
<!-- 已有图片：|gradW| 曲线在 0~15 范围波动，|gradBias| 曲线永远 ≤1，量级差一个数量级 -->

### 问题四：每次都看全部数据

每走一步，都要把 12 个点从头到尾算一遍。12 个点还好，但如果有一百万个点呢？每走一小步就要算一百万次——太慢了。

而且每次都走同一条路——没有随机性，没有"碰运气"的机会。万一起点不好呢？
