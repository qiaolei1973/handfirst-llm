# 架构图设计

不是所有图都适合用同一种画法。本文讨论**什么时候用什么图**，以及每种图的设计思路。

---

## 三种基础图类型

### 计算图（Computational Graph）

**表达什么**：数据如何一步一步被变换，导数如何一步一步回传。

**特征**：节点是值（圆），边是操作（箭头+偏导数标注），正反向流在同一组边上。简洁、数学化。

**适合**：解释算法过程——反向传播、链式法则、梯度流向。

**设计要点**：
- 一张图只讲一个数据流路径（一段计算），不要把所有层都堆进去
- 边上标局部偏导数比在旁边写公式更直观——读者同时看到"哪到哪"和"怎么变"
- 用颜色区分"前向计算的值"和"反向回传的梯度"——同一条边，两个方向，两种颜色
- 配合渐进披露：一图多态，逐步高亮

**经典参考**：Chris Olah, *Calculus on Computational Graphs* (2015)

---

### 结构图（Structure Diagram）

**表达什么**：概念之间的层级、组成、递进关系。从简单到复杂，逐步构建认知。

**特征**：容器（虚线矩形）嵌套或并排，模块间用递进箭头表示"基于此构建"。形状和颜色承载语义——同概念同形状同颜色。

**适合**：解释架构——"一个神经元是什么"→"一隐藏层是什么"→"完整网络是什么"；组件层级关系。

**设计要点**：
- 从左到右、从上到下都可以——关键是递进方向要一贯
- 每个"阶段"用一个容器框起来，容器标签说清楚这个阶段的主题
- 跨阶段传递的概念（如"神经元"）在所有阶段里用一致的视觉元素
- 递进箭头用虚线 + 低透明度，暗示"这不是数据流，这是认知递进"

---

### 流程图（Flow Diagram）

**表达什么**：一个循环或流程的步骤序列。

**特征**：步骤节点（圆角矩形），箭头连接，返回箭头闭合循环。

**适合**：训练循环、数据 pipeline、算法步骤序列。

**设计要点**：
- 循环的返回箭头是关键——让读者看到"这是一个圈"
- 循环外的辅助概念（正则化、early stopping、标准化）用小节点 + 虚线引入
- 每个步骤一种颜色，箭头颜色跟源节点走

## 如何选择图类型

先回答三个问题，再决定用什么图：

1. **这张图要回答什么问题？**（不是"我要画什么"，是"读者看完要理解什么"）
2. **核心关系是什么？**（数据流过步骤？概念层层构建？循环反复？）
3. **需要分步展示吗？**（如果算法有 5 个阶段，是否需要 5 张图或渐进披露？）

| 核心关系 | 图类型 | 例子 |
|---|---|---|
| 数据逐步变换 + 导数回传 | 计算图 | 反向传播 |
| 概念从简单到复杂的递进 | 结构图 | 神经元 → 隐藏层 → 网络 |
| 步骤序列 + 闭环 | 流程图 | 训练循环 |
| 抽象概念间的层级关系 | 结构图 | 概念地图 |

## 设计流程

1. **写提纲**：先用文字把要表达的核心关系写清楚
2. **选图类型**：按上面的对照表选
3. **列概念清单**：图中会出现哪些独立概念？每个配一种颜色
4. **画骨架**：先画节点和边，不加文字；检查布局是否清晰
5. **加标签和标注**：能放在边上的不放在旁边，能放在节点里的不单独写
6. **对照检查**：同一个概念在前面的图里用过吗？颜色一致吗？
