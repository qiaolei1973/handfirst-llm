# 结构图（Structure Diagram）

## 表达什么

概念之间的层级、组成、递进关系。从简单到复杂，逐步构建认知。

## 识别特征

- **容器**（虚线/实线矩形）表示一个语义范围——"这一块讲的是隐藏层"
- 容器之间**并排或嵌套**，模块间用递进箭头表示"基于此构建"
- 形状和颜色**承载语义**——同概念同形状同颜色，跨图一致
- 常见布局：水平多栏（左→右递进）或从上到下

## 什么时候用

需要解释"一个复杂系统是怎么从简单部分组合起来的"。典型场景：

- "一个神经元 → 一个隐藏层 → 完整网络" 的递进解释
- 组件层级关系
- 概念地图（分类和归属）

## 什么时候不用

- 数据逐步变换的过程（用计算图）
- 步骤序列 + 循环（用流程图）

## 设计要点

- **递进方向要一贯**——决定左→右就每个阶段都左→右
- **每个"阶段"一个容器**——容器标签说清楚这个阶段的主题
- **跨阶段一致**——同一个概念在所有阶段里，用同样的形状、颜色、标签
- **递进箭头用虚线 + 低透明度**——暗示"这是认知递进，不是数据流"
- 容器内可以嵌套子结构，但别超过两层——太深了读者失去方向感

## 与计算图的区别

计算图问"数据经过了哪些变换"，结构图问"它由什么组成"。
