# Excalidraw 绘图规范

本文档记录用 Excalidraw 画图的**原则**——不是具体配色表，而是如何做选择的思考方式。

---

## 生成流程

- **源文件**：`.excalidraw` 放在 `apps/_docs/scripts/<vn>/`。
- **渲染**：`cd apps/_docs/scripts && npx tsx generate-all.ts` → 输出 `apps/_docs/public/<vn>/<name>.svg`（excalirender 渲染，按源文件 sha256 缓存）。
- **引用**：markdown 里写 `![...](/vn/<name>.svg)`。
- **画图**：可用 `excalidraw-diagram-generator` 技能生成 `.excalidraw`；本文件定义风格。

---

## 元素选择

| 元素 | 语义 | 什么时候用 |
|---|---|---|
| **圆** `ellipse` | 一个值、一个变量 | 节点是"数据"而非"操作"时——计算图中的 x、z、L；输入和输出 |
| **圆角矩形** `rectangle` | 一个操作、一个组件 | 节点是做某件事的——Linear、ReLU、Layer；流程步骤；容器 |
| **箭头** `arrow` | 数据流向或依赖关系 | 前向数据流、梯度回流、模块间递进 |
| **直线** `line` | 分隔、分组、括号 | 不在节点间传递信息，只做视觉分区 |
| **文字** `text` | 标签、标注、标题 | 单独标注时用 text；节点内嵌文字省一个标签 |

**原则**：形状承载语义。一旦选了"圆 = 值，方 = 操作"，全图保持一致。不要让读者猜为什么这个值是方的前面那个是圆的。

## 颜色体系

颜色在教学中不是装饰——它帮读者**跨图识别同一个概念**。

**核心原则**：
1. **同概念同色** — 一个概念在所有图里用同一组颜色
2. **先分语义，再选色** — 先列出有哪些独立概念，再给每个分配颜色
3. **饱和度表达重要性** — 核心概念用鲜艳色，辅助信息用灰色
4. **一套配色定义一次** — 放在 master 文件里，后续图复用

**常见语义 → 颜色的对应**（参考，不是规定）：

| 语义 | 典型色系 |
|---|---|
| 输入/输出 | 灰 `#e2e8f0` |
| 线性变换、中间值 | 蓝 |
| 激活、非线性 | 黄/橙 |
| 预测、最终输出 | 绿 |
| 错误、损失 | 红 |
| 可学习参数 | 紫 |
| 梯度/反向流 | 红（但要用粗细区分方向和强度） |
| 注释/辅助信息 | 浅灰 |

**灰度测试**：把图转成灰度，如果活跃元素和其他元素区分不出来，说明颜色对比度不够。

## 布局

- **计算图**：水平（左→右 = 输入→输出），符合阅读习惯且省竖向空间
- **结构/层级图**：水平多栏并排，每栏内部纵向
- **循环图**：水平排列 + 曲线返回箭头
- **间距**：紧贴但不重叠；主节点间距比子节点大；标题留足呼吸空间

## 渐进披露（Progressive Disclosure）

当一个图需要分步解释时，不要在 markdown 里写 N 个独立的图——用一个母版 + 脚本生成步骤变体。

**做法**：
1. 一个 `.excalidraw` 母版，包含所有节点和边
2. 每个元素用 `groupIds` 标记它属于哪些步骤
3. 全局可见的元素标 `"all"`
4. Python 脚本读取母版，对每个步骤：活跃元素 opacity = 100，其余 = 15
5. 构建流程中自动执行脚本，产物 gitignore

**关键**：永远只编辑母版。步骤文件是生成产物，不要手改。

**dim 透明度选择**：15% — 刚好能辨认位置但不会抢注意力。太暗（5%）读者不知道灰色部分是什么；太亮（25%）和活跃元素混淆。

## 常见陷阱

**多点箭头转角断开**：roughjs 对 >2 点的线性路径在转角处不连接。已修复（excalirender `multiPath()`），但仍建议：能拆成直箭头就拆。弯曲线不要多于 3 个转折点。

**文字被框截断**：先估好宽度再写标签。两行文字的圆/矩需要比单行大 ~40%。

**同一概念在不同模块里颜色不一致**：这是最常见的问题。画完一个图后，对照前面的图检查关键概念的配色是否一致。
